Agents can use saved 1Password Connect credentials directly with `run_with_secrets`, under the existing agent access setting and Connect token permissions. No Share, grant ID or additional permission is required. Agents discover field IDs and labels without values, then name the environment variables to inject. Values stay outside the model context and are masked in command output. Native commands run in the calling agent’s working directory; legacy MCP Connect commands run in the plugin process working directory.

Secrets provides private text, image and credential-file input through single-use or reusable execution grants, and optional 1Password Connect access for agents. Private inputs are encrypted to a short-lived request key before leaving the app. Unconfirmed submissions can retry the same ciphertext without creating another grant. Private-input values stay outside the conversation; Connect item reads return field values only when plaintext access is explicitly enabled. The request appears as a question card in the current conversation. Fill one field at a time, use the tabs to revisit answers, and select Next or Submit secrets. Completed fields show a check. Select Skip to omit the current field and clear its input, or revisit a skipped field to fill it. Skipping the last field submits the completed selection; skipping every field finishes without creating a grant. The agent receives the skipped field names. Submitting creates a single-use or reusable grant and sends the agent its identifier. You can decline a request or revoke an unused grant. **Secrets** beside the composer opens the saved Connect connection’s secret list, automatically loading the first accessible vault. Switch vaults or filter by title, and select **Provide secrets** when you want to enter private input or review pending requests and output. Desktop uses a popover and compact layouts use a sheet. `/secrets` adds an inline form. None of these entries opens a workspace tab.

Text fields become environment values in a separate child process. Image and file fields become environment variables containing temporary file paths. File fields optionally specify `format: "json" | "pem" | "any"`. Each file is limited to 128 KiB; the broker validates its encoding and requested format. Images and credential files share a 4 MiB combined limit. Desktop and browser clients can select a file; text file contents can also be pasted into the private form. Binary files retain their exact bytes. The child runs in the selected agent's directory. PNG, JPEG and WebP uploads are available on desktop and browser clients, up to four images and 4 MiB combined. Native mobile clients support text input and output review; their plugin SDK does not yet expose an image picker.

For text-only grants, exact secret values are replaced with `[REDACTED]` in the process output. If a grant includes an image or credential file, **all stdout and stderr are withheld from the agent**. Open **Review output**, edit the text if needed, and select **Release output** or **Discard output**. Only the text you release becomes available through `read_secret_output`. Releasing it permits it to enter the model context and conversation history. The plugin does not try to infer whether OCR or other derived content is safe.

Requests, unused grants and held output expire after ten minutes. They live in host plugin memory and disappear on plugin reload. The broker removes expired output during its periodic cleanup. Images and credential files are written to private temporary files only while the consuming command runs and deleted afterward. A host or broker crash can leave temporary files behind; the next successful plugin start cleans its image directory. Deletion is not secure disk erasure. Input values and unreleased output are excluded from ordinary attachments, drafts, timeline data and query/mutation caches.

To use 1Password Connect, open Settings → Plugins → Secrets → ⋯ → 1Password Connect and save your Connect server URL and access token. The configuration survives plugin reload and daemon restart. If the daemon needs a proxy to reach Connect, including Tailscale userspace networking, set an HTTP(S) or SOCKS5 proxy URL. You can save it separately without re-entering the Connect token. All Connect traffic then uses that proxy, retaining HTTPS certificate validation; proxy failures do not fall back to a direct connection. You can test the saved connection, disable agent access without deleting credentials, or delete the saved configuration. The client can browse vaults and item metadata, filter titles and refresh lists even while agent access is disabled. The compact list shows titles and categories. **Share with agent** reads the selected item on the host and creates a ten-minute, single-use or reusable execution grant from its non-empty text fields. Only field names, the grant ID and execution instructions are sent to the current agent; values remain outside the conversation. Sharing requires enabled agent access. Listing alone does not fetch secret field values.

Connect tools list vault and item metadata. A separate Allow plaintext reads and writes setting permits full-item reads, creates and replacements; their results include field values in agent context and may be sent to the selected agent provider. Plaintext access defaults off, including for existing configurations, and is independent of grant sharing. Replacing a saved connection resets plaintext access to off. The setup token is encrypted in transit to the plugin. This access is shared by callers of the host's loopback MCP endpoint rather than restricted by a per-agent grant. The token is stored as a plaintext file accessible to the daemon user, same-user processes, administrators and backups; it is not returned to the client. Use a token limited to the vaults and operations you intend agents to access. See [Connect setup and tool contracts](README.md#1password-connect).

Requires Paseo 0.15.1 or later on both daemon and client, and a macOS or Linux daemon. Interactive sessions receive native tools when opened, resumed or refreshed, with the calling agent identity supplied by Paseo. Native execution and output reading are scoped to that agent. Previously configured loopback MCP clients remain supported with bearer grant/output identifiers. New sessions need no separate MCP setup. The plugin uses your existing Paseo connection; an authenticated encrypted connection remains required.

Commands have a two-minute deadline and a combined 1 MiB output limit. Excess output is discarded. Interactive commands and background services are unsupported. Admission is bounded to eight concurrent commands, 64 pending grants, approximately 32 MiB of pending input and 16 held outputs.

The child process can read, encode, write or transmit its inputs. It runs as the daemon user with filesystem and network access. Separate-process execution and output review prevent accidental disclosure through the normal tool-result path; they are not an operating-system sandbox. An agent with equivalent host access can bypass that path. Grant and output identifiers are bearer capabilities at a loopback-only MCP endpoint, not authenticated per-agent identities. Managed-runtime strings, swap, crash dumps and same-user inspection are outside the plugin's protection.

Use Private input connection in the plugin settings to test the encrypted submission path with dummy data. Requested-input notifications wait for the agent to be idle and expire with the grant. Encryption still requires a trusted Paseo connection.

Choose **One use** (default) or **Reuse for 10 minutes** when submitting private inputs or sharing a Connect item. Reusable grants remain available to the same agent after successful or failed executions until their original ten-minute expiry or revocation. Reloading the plugin clears grants. Revocation prevents future executions; commands already running finish normally. Each file execution still uses fresh temporary files and holds output for review.
