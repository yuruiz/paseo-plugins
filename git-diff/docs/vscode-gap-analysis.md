# 与 VS Code 源代码管理的差距

参考 [VS Code Source Control 与 Diff Editor](https://code.visualstudio.com/docs/sourcecontrol/overview)，本次把插件重做为紧凑的只读审阅面板，保留递归子模块、独立 HEAD 与 `ignore = all` 支持，并继续落实多文件标签、语法着色、静态预览和持久设置。

## 当前视觉与交互规范

- 侧栏默认 240px，可在 180–600px 之间拖动，并为代码区保留至少 360px；双击边缘或 Home 恢复默认，左右方向键每次调整 10px。侧栏可隐藏。
- 编辑器只保留 36px 标签栏和约 30px 的路径工具栏。图标按钮具有真实悬停提示、辅助名称和键盘焦点；显示选项集中在设置。
- 文件行桌面 28px、紧凑模式 38px；仓库行 34px。文件名、父路径、Git 状态和部分暂存标记分层展示。
- 文件类型拥有不同形状与颜色：TS、JS、React、Python、Rust、Go、HTML、CSS、JSON、YAML、Markdown、Shell、SQL、图片、Docker 等；采用真正的 vscode-icons SVG，原生端使用 PNG；操作按钮采用 Codicons，均离线打包，来源见 [第三方资源](third-party-notices.md)。
- 打开文件新增标签，重复打开复用已有标签；提供独立关闭按钮、相邻标签回退、普通滚轮 / 触控板 / 滚动条横向浏览。关闭全部标签后显示选择文件提示。
- 各语言的关键字、字符串、注释、数字、类型、函数、属性和标签分别着色；旧侧与新侧维护独立的多行注释 / 字符串状态。浅色与深色使用相应调色板，增删行底色、正负号与行号仍独立可辨。
- 小于 720px 使用独立列表 / 差异页；代码区不足 650px 自动统一对比，宽度恢复后保留原先的左右布局偏好。
- 仓库标题随当前分组吸顶。侧栏按钮固定在标签栏右端，不参与横向滚动。左右对比中线可拖动、双击复位与键盘调整，比例持久化；两侧水平滚动独立，垂直行仍共享一份虚拟列表。
- 默认字体对齐 Paseo 的系统 UI 与 SFMono/Menlo 等宽栈，代码默认 13px / 500；可选字体、字重与自定义已安装字体，设置中提供示例。旧版 SDK 没有字体 token，采用宿主默认值和 Web UI 字体变量。
- 文件与差异列表保持虚拟化。纤细滚动条只作用于插件及其设置，不改变宿主界面。

## 对照

| 方面             | 原界面                 | 当前结果与剩余差距                                                                                                  |
| ---------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 信息密度         | 多行路径与大量文字按钮 | 两行编辑器工具区、图标与 tips、可隐藏/拖动侧栏；代码区获得更多空间                                                  |
| 文件图标         | 无类型区分             | 按语言、文档、图片、配置等区分图形和颜色                                                                            |
| 标签             | 单个文件名被替换       | 多文件追加、复用、批量关闭与横向滚动；默认保留最近 5 页及滚动位置，可选 1–10；未提供拖拽排序与固定标签              |
| 代码颜色         | 只有差异颜色           | 语言相关词法着色与多行状态；仍缺少语义 token、词级差异高亮、完整 TextMate 语法                                      |
| 文件组织         | 仓库下平铺             | 仓库/分支、文件筛选、列表/目录树、独立折叠与部分暂存提示                                                            |
| 暂存与未暂存     | 文字切换               | 紧凑比较标签，明确 HEAD/暂存区/工作目录；未像 VS Code 同时显示两组资源                                              |
| 键盘             | 主要依赖点击           | 列表方向键与 Enter、筛选后打开匹配项、F7 差异块、Ctrl+PageUp/PageDown 标签、Ctrl/Cmd+W 关闭；筛选可重新展开隐藏侧栏 |
| 预览             | 无                     | Markdown 常用结构、代码块与离线 Mermaid、文件/网页/标题链接、HTML 静态页面、常见图片；工作目录与暂存区读取正确来源  |
| 文件菜单         | 无                     | 侧栏/标签复制绝对与工作区相对路径、定位宿主 Finder；标签支持当前/其他/左右/全部关闭                                 |
| 设置             | 仅面板临时状态         | Paseo 主机持久存储、字段级冲突合并、串行保存、错误重试和恢复默认；打开的标签仍属于当前面板会话                      |
| 加载与错误       | 初始加载               | 保留旧列表、手动刷新、补丁重试、迟到响应隔离、设置失败可恢复                                                        |
| 子模块           | 递归读取               | 保留递归、ignore 与独立 HEAD，并显示指针变化和分支                                                                  |
| 大仓库           | 串行元数据读取         | 12 路元数据读取、6 个 Git 进程上限、未跟踪统计复用、快照合并、容量受限补丁缓存                                      |
| 自动刷新         | 固定 2s                | 默认 2s，可选 5/10/30s；暂停、后台停止、失败退避、前台恢复；仍缺少文件监听与增量资源事件                            |
| Git 写操作       | 不提供                 | 暂存、取消暂存、丢弃、提交、同步与分支切换仍未提供                                                                  |
| 提交历史         | 未提供                 | GitLens 风格彩色提交图、分支 / 标签筛选、搜索定位、分页、提交详情及相对父提交的历史 diff，支持主仓与子模块          |
| 完整编辑器与历史 | 轻量 diff              | 仍缺少编辑、行/块级暂存、三方合并、差异概览尺、blame 与任意 ref 对比                                                |

“全部”逐仓比较 HEAD 与工作目录。如果先暂存再反向修改，使工作目录恢复 HEAD，两部分可能抵消；已暂存和未暂存视图可分别查看。

## 设置与预览边界

设置按「外观、代码、比较、行为」四个 Tab 分类，选项较多的配置使用下拉；顶部分类和底部保存状态固定，只有内容滚动。切换分类不改写配置。设置通过 Paseo 的 host-scoped settings 存储，重开面板与主机重启后可读取。持久化比较范围、列表/目录树、侧栏宽度与显示、左右对比比例、布局、语法着色、字体、字重、字号、Tab 宽度、行号、换行、上下文、忽略空白、默认预览、标签缓存数量、滚动条、自动刷新和刷新间隔。普通设置立即提交，拖动合并频繁修改并在松手时提交；有冲突时读取最新版本，只合并本次改动字段。

Mermaid 使用官方 12.3.0 完整引擎，按需从主机传输约 2 MiB 压缩数据，当前客户端缓存，不纳入启动时的客户端脚本。图表在允许可信脚本的独立无同源 iframe 中绘制，使用 nonce CSP、strict 模式和资源禁用策略；错误时展示源码与错误。每份最多 16 张图，每图最多 20000 字符、500 条边。

Markdown 支持标题、段落、强调、列表、任务、表格、引用和围栏代码，原始 HTML 作为文本；并非完整 CommonMark/MDX 引擎。超长或异常括号密集的行回退纯文本。相对或远程图片显示占位，未接入本地资源重写。HTML 在 sandbox iframe 中静态预览，不运行脚本、不加载外部或相对资源；不替代开发服务器。图片支持 PNG/JPEG/GIF/WebP/SVG/ICO/AVIF/BMP，也能读取暂存区图片的原始字节。

格式化 Markdown 与 HTML 预览面向桌面/Web；原生移动端当前回退文本，图片使用原生组件。Finder 命令在 daemon 主机执行，远程连接时定位的是远端文件。常规预览属于当前变更列表；Markdown 链接可读取工作区内未修改文件，按文档相对路径或工作区根路径解析，并优先匹配最深子模块。文件链接与内容读取校验实际路径，拒绝越界、Git 内部文件和指向外部的符号链接；不修改业务仓库。

## 性能证据

`npm run benchmark`，2026-11-04，macOS arm64 / Node 22.23.4，本机单次测量：

| 操作                  |             耗时 |
| --------------------- | ---------------: |
| 1000 变更文件首次扫描 |         332.07ms |
| 同仓库复扫            |         186.59ms |
| 快照缓存              |           0.02ms |
| 补丁首次 / 缓存       | 10.08ms / 0.03ms |
| 10000 文件树 / 筛选   |  4.83ms / 0.85ms |
| 5000 行语法状态预处理 |          27.15ms |
| 40 行词法着色         |           0.37ms |

浏览器输入 5000 个文件、5001 行补丁，只渲染 47 个文件按钮与 9619 个差异文本字符；代码使用 6 种可区分颜色，可跳转到第 10000 行所在差异块。着色保留虚拟化，不为全部补丁创建文本节点。标签重名计数为线性构建。

这些是本机单次测量，不代表所有仓库的延迟/FPS 保证，也未与相同环境下的 VS Code 速度排名。完整数据见本地 `artifacts/performance.json` 与 `artifacts/editor-upgrade.json`。

服务端补丁缓存最多 24 项、估算 8 MiB；面板默认保留 5 个已挂载标签，最多 10 个；每页最多缓存一份当前差异，按估算 24 MiB 总内容预算提前淘汰旧页，当前页始终保留（并非实际堆内存上限）。相同请求合并，失败不缓存，文件版本变化后重读；未跟踪统计最多缓存 10000 项。保留单文件/预览 1 MiB、补丁 2 MiB、Git 子进程 15s 的读取边界，状态扫描不逐文件读补丁。分支来自已有 status，关闭领先/落后计数。

## 后续优先级

1. 补同时显示暂存/未暂存资源组及文件级暂存、取消暂存，再扩展提交，明确部分暂存、冲突与子模块所属仓库。
2. 文件监听、增量状态与请求取消，进一步减少大仓库轮询负担。
3. 词级/语义高亮、差异概览尺、标签排序/固定与跨会话滚动位置恢复。
4. 完整 Markdown 及本地资源解析；按需接入可运行网页的开发服务器预览。
5. 扩展任意 ref 历史对比、分支操作、远端同步与合并工作流。

完整验收范围见 [验证记录](verification.md)。

2026-11-05 缓存验收：10 个各 5000 行的文件依次打开共 2.63s，在数量配置为 10 时按内容预算保留 5 页；缓存切换没有内容请求且保留 1400px 滚动位置。10 个短文件可同时保留，页面 live DOM 为 728 个节点。这是单机样本，详细边界见验证记录。左右 / 统一是仅有的两种布局，旧补丁布局自动迁移为统一。
